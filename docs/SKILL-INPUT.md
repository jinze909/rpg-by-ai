# 战技冷却末段输入 · Skill cooldown input window

Q／手柄Y原先只在冷却完全结束后接受输入，即使只剩0.01秒也会拒绝。本功能沿用已有的0.20秒战技输入窗口，在冷却最后几帧记录一次请求，减少连续战斗中的丢操作。

## 操作与费用

- 当前耐力足够、战技冷却不超过 **0.20秒** 时，按一次Q／Y，或点击普通、紧凑HUD上的战技格，可预输入一次。技能格仍显示真实冷却，未就绪时不提前显示绿色就绪框。
- 请求捕获当时的方向、目标点和武器／职业／打法／战技身份。之后移动瞄准点或轮换锁定目标，不会改写这次请求的方向与目标；实际伤害、遗物效果与费用仍在真正起手时按原规则取得。
- 冷却与动作恢复同时推进，按两者中更晚的就绪时间判断，不把等待时间相加。只有在短窗口内真正就绪才开始技能。较早的输入会被拒绝；等待超过窗口的请求会失效，不会在很久以后自动施放。
- 排队时不扣耐力、不触发治疗或防护、不开始新冷却，也不取消正在进行的攻击。起手时重新检查耐力，沿用原来的40耐力（对应遗物为50）与3.5秒冷却，支付一次、施放一次。
- 新的有效战技请求取代较早的待执行闪避；新的有效闪避请求清除待施放战技。被拒绝的战技请求不会抹掉仍有效的闪避。持续按住普攻不能抢走已接受的战技请求。

## 暂停、训练与存档

命中停顿冻结战斗冷却与短窗口。视觉检查场的模拟暂停也保留同一份冻结状态，恢复模拟后继续；这不代表原生运行验收。

菜单、应用暂停、换地区、读档、新游戏、死亡、武器／职业／打法／战技身份变化和训练重置／退出沿用原来的输入清理行为。训练目标已经清空时，待执行技能会在进入回顾前丢弃，不会趁清场额外扣费。单纯保存不执行、不复制请求；请求不进入SaveData，不新增版本或迁移字段。

原来的攻击恢复／闪避结束战技缓冲、技能伤害与效果、飞行中的攻击快照、闪避费用和无敌时间保持。浮点末帧使用与闪避一致的微小数值容差，不缩短实际战技冷却。

## 验证边界

`tools/run_skill_cooldown_buffer_core_checks.py` 验证窗口边界、可变帧间隔、捕获目标、费用、输入优先级与生命周期；完整Core回归继续保留原有检查。
