# 收招、受击、倒地、预警与绘制连续性

本轮接续固定比例与头部注册版本。沿用金发 Viola 主角、三职业、原地图、数值、任务、装备与存档；没有新增职业、地图、怪物或玩法，也没有重新生成角色身份。

## 修复

| 问题 | 共同规则与改动 |
| --- | --- |
| 站着收招时移动鼠标，身体提前换方向 | 起手、命中和站立收招使用同一次捕获的朝向；实际恢复移动时，身体与腿一起回到行走朝向。 |
| 受击后退时被旧行走方向或新鼠标方向扭转 | 真正受到伤害时记录身体朝向，受击期间沿用。后退由碰撞扫掠处理，不伪装成行走。 |
| Q 暂时使用职业武器，死亡却突然换回另一套装备 | 倒地前保存正在显示的装备与身体方向；死亡动作不受后续输入影响，回到旅店才解除临时外观。存档仍保存原装备。 |
| 向左的普通怪或 Boss 倒地时翻到右边 | 活体、闪白和遗体共用侧向镜像规则。近乎竖直的微小 X 变化不再反复翻面。 |
| 射手后撤时背对玩家，起手又突然转身 | 后撤保持面向玩家，倒序播放距离驱动的迈步；受击位移不产生迈步或后撤状态。 |
| 行走时强化光效与护盾提示消失 | 移动、站立和动作分支共用附加效果绘制；HUD 轮廓重绘不再重复这些效果。 |
| 普通近战前摇缺少真实危险范围 | 薄扇形预警读取实际近战的中心、1.5 单位半径和角度界限；伤害时机、攻击力与范围均保留。 |
| 射手预警从脚底发出 | 四方向预警使用真实弓口与发射高度，和原箭的出生规则一致。 |
| 举起的 Boss 武器、远端预警可能被 HUD 遮盖 | 为 22 张角色图集的 292 帧预计算全部非透明像素边界；敌人的当前帧、镜像、密度与脚底决定 HUD 遮挡范围。玩家包含所有职业武器的像素包络。预警进入 HUD 时也触发淡出和危险提示重绘。 |
| 同深度对象绘制不稳定 | 地面深度之外使用固定插入顺序处理相同深度，保留原场景与角色的前后层级。 |
| 每个 GUI 事件创建场景列表、闭包和 HUD 列表 | 复用有容量的绘制条目、排序器与独立 HUD/指针区域，改为直接绘制调用。AI、飞行物、溅射、环境危险和镜面光路复用分开的临时容器，保持移除敌人、清除敌弹和生成援军时的原先迭代顺序。 |

角色密度、256 人物图格、240 脚底锚点、固定头部、44 张启动前生成的遮罩，以及原来的四方向玩家动作继续沿用上一版规则。没有通过缩放身体或上下抖动代替迈步。

## 已执行的检查

- 43 组生产 Core 回归通过，包括三职业四方向收招、换装备后的职业 Q 倒地、受击朝向、射手真实后撤、四方向近战命中/落空、Boss 死亡与爆炸溅射同时移除对象、Boss 生成援军。原存档、剧情流程、关卡阻挡、快速闪避碰撞、30 秒连续移动和声音事件回归一并通过。
- 1352 个离线生产 GUI/布局记录，潜在文本溢出为零；原三职业、十个场景与八个 Boss 的动作时间轴保留。
- 原有 156 种玩家、84 种同伴、99 种敌人/Boss 状态组合继续通过；另检查 48 种移动护盾/强化状态及 88 种怪物/Boss 朝向、当前帧像素范围和倒地组合。
- 从实际纹理像素逐一核对敌人的当前帧边界；包含举起武器、迈步、前摇、释放、受击和两侧朝向，不在战斗中扫描纹理。
- 24 个相同地面深度的敌人连续绘制 8 次，检查稳定顺序、临时容器复用、HUD 与鼠标操作保护。此项验证分配规则，不能推导实机帧率。
- 森林 Boss 从原祭坛启动，连续 523 个 20ms 逻辑帧战斗至胜利，保留并结束死亡流程，记录 103 帧离线画面。
- 121 张 PNG、404 个图格、219 个 Unity GUID、1209 个字体字符检查通过；原主角文件与地区/物品/Boss 数据保留。
- 公开导入入口在隔离副本中生成 22 张角色图集、44 张遮罩、头部注册和像素可见边界，与交付资源逐字节相同。生产 Editor 的 75 张纹理导入规则与 C# 语法检查通过。

## 原生验证边界

本环境没有 Unity Editor/Player。上述是实际生产 C#、资源像素和绘制调用的离线验证，不能据此宣称每个像素的实机效果、音效试听、GPU、手柄或帧率全部验收。

工程中 `Starfall > Visual QA > Open Review Lab` 支持冻结/逐帧推进并隔离旅程存档。原生 Test Runner 已加入本轮核心回归。实际 Game View 应重点连看移动→攻击→收招→移动、快速换瞄准方向→受击→倒地、射手后撤→拉弓，以及 Boss 举起武器与危险范围进入 HUD 的全过程；性能验收需同时查看 Profiler 的 GC Alloc 与帧时间。
