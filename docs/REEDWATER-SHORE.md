# 旧路河岸：水格内的岸缘过渡

本单元接续 `b67903b`，仅替换 room11 原有的四边等宽暗条与连续泡线。72×48 地图、碰撞、两条常通路线、可修桥、根路、探索记录、敌人和奖励全部保留。水底仍是原 TerrainVariants 的完整、不透明 36×36 提交，图格、UV、稳定种子与着色均不变；不新增可站立的浅滩。

## 生产路径

- `DrawTerrainEdge` 只在旧路河岸调用 `DrawReachShore`，其他地图沿用原水岸。原墙边、视口外两格提前绘制、场景排序、危险提示和主角完整帧路径不变。
- 每次绘制读取 `Game.PresentationTile` 的八邻接。四个正交邻居确定岸侧；相邻两侧仍为水时，斜向陆地才产生圆形内角。修桥后12格水面按原规则成为桥面，周边八格水岸立即重新选择遮罩；根障碍到陆路的变化不会虚构水岸。
- `PixelArt.PrewarmReachShores` 在 Awake 准备46种非空拓扑的两个稳定变体，共92张48×48 Point/Clamp、无 mipmap 的透明遮罩，RGBA32 像素合计828 KiB。全开阔水不生成遮罩。纹理随原 PixelArt 生命周期销毁；绘制阶段只查缓存，不创建纹理、拼接键名或扫描整张地图。
- 沉水暗唇、青绿浅水层与稀疏泡沫全部位于当前水格内部，向河心衰减。圆角混合仅作用于16源像素的浅水支持域，避免两岸交会把本应透明的深水重新涂色。两变体只改变内部细节；相邻水格端点的 RGBA 一致。
- 变体由世界坐标选择，和帧时钟、小数镜头、语言、窗口大小及特效档位无关。最低特效及减少动态保留同样的岸缘信息。每个受影响水格最多一次额外遮罩提交；这不是原生帧率或 GPU 性能测量。

## 验证与边界

`tools/run_reach_shore_checks.py` 使用生产 OnGUI、真实输入和 SaveStore，离线声明提供纹理像素。检查覆盖实际459个水格、所有256个输入邻接/47个规范拓扑、预热与销毁、可相邻拓扑与两个变体的精确像素接续、连续镜头、原不透明底图、实际修桥/根路、只读绘制及 v1/v2 旧存档。CI 保留全部旧检查并新增此脚本。

同一脚本的 `--baseline-ref b67903b` 只读归档旧生产源码，必须先编译成功再因缺少新岸缘语义变红；不切换工作树。`--capture-only --capture-dir .starfall-checks/layout` 只录制画面，不表示检查通过。

本轮冻结源码实测：新增 Runtime **5/5**，旧基线成功编译后 **0/5** 语义失败；实际459个水格中263格有岸缘、196格河心透明。2,048种局部陆水排列产生338对可相邻拓扑，四种变体配对共64,896次精确 RGBA 接缝比较全部通过；328帧小数镜头覆盖中英/两种窗口/低高特效。真实 E/数字修桥、R 开根、v1/v2 SaveStore 与绘制只读断言通过。原地图可见性3/3、河岸玩法4/4、威胁轮廓4/4、主角 A–E及六种故障注入、五阶段真实 Unity DLL 编译、离线 Editor 语法/75项导入规则、275组元数据/7项检查器自测及 LFS fsck 通过。475个受保护基线文件（含273份旧元数据、87项 LFS 引用）保持字节或 LFS OID 一致。

离线前后对照包含入口、桥关闭/开启、根路关闭/开启及连续岸线，中英大字、960×600最低特效/减少动态与1920×1080高特效共24对。记录由原 OnGUI 生成，再以 Pillow 近似合成用于视觉检查；截图与日志只保存在 ignored 的 `.starfall-checks/shore-*`、`layout/qa-shore-*`、`qa-previews/qa-shore-*`。
