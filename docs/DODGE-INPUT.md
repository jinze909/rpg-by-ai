# 闪避输入窗口 · Dodge input window

闪避原先只响应按下瞬间：冷却尚余数帧时按空格或手柄A，操作会直接被拒绝，必须再按一次。本功能在冷却末尾保留一次短暂请求，减少这种丢操作的感觉。

## 操作规则

- 当前耐力足够、闪避冷却剩余不超过 **0.12秒** 时，可提前按一次空格／A，或点击HUD闪避格。空格／A捕获按下时的移动方向；静止或点击HUD时使用当时瞄准方向。之后转动鼠标或摇杆不会改变这次已记录方向。
- 冷却转好才开始闪避、扣一次耐力、进入无敌并取消当前攻击。排队期间不会提前扣费、取消当前动作或提供保护。按住按键不会自动续闪；另一有效闪避请求只替换这一条待执行请求。
- 更早的按键、耐力不足、无效方向与训练清场后的操作不排队，也不会等待之后的耐力回复。执行时会重新核对状态与费用。
- 新的有效Q／Y战技请求取代尚未开始的闪避请求；新的有效闪避请求清除旧的待施放战技。已经开始的闪避之后同帧按Q／Y，仍使用原有0.20秒战技缓冲。持续按住普攻不会吞掉待执行闪避。

待执行闪避存活期间，持续按住J／手柄X／鼠标左键不会新起一次普攻、抢走其耐力；窗口结束后普攻恢复原节奏。已有的攻击仍可继续到闪避真正起手时被取消。这项优先级不预留耐力，也不改变执行时重新核对费用的规则。

闪避原有20耐力（对应遗物为25）、0.18秒移动、0.32秒无敌、移动速度与天赋冷却公式保持原值。现有攻击／受击动作仍可在闪避就绪时立即取消，不增加新的动作锁。窗口沿用战斗模拟时间；原命中停顿冻结它，暂停菜单与应用暂停则直接丢弃待执行请求。

开放地面上的完整闪避固定移动 **2.7格**（0.18秒 × 15格/秒），斜向使用同一总距离。末帧只按剩余闪避时长移动，不再因20／30／50 FPS多走到3格，或因60／120 FPS走到2.75格；20ms帧间隔的浮点余量也不会多出一整帧。末帧不附送普通行走，下一帧再按原规则走路或起手。墙体、门与树木仍通过原碰撞扫掠阻挡／滑行，实际受阻距离可以更短；已记录方向、费用、无敌和冷却的模拟时钟不变。

## 界面与保存

普通和紧凑HUD均可接受最后0.12秒的点击，仍显示真实剩余冷却，未就绪时不提前显示绿色就绪框。战技格另有最后0.20秒的预输入窗口，见 [SKILL-INPUT.md](SKILL-INPUT.md)；其余动作格的可用条件不变。

请求只存在于内存，不新增存档字段。菜单、应用暂停／失焦、死亡、读档、新游戏、换地图、装备／打法／战技切换及训练重置／退出会清除它；返回游戏不会凭旧按键突然闪避。保存本身不制造或重复请求。

## 验证边界

核心检查验证不同帧间隔下的末帧、方向快照、单次费用、拒绝路径、意图优先级及生命周期清理；`python3 tools/run_core_tests.py` 同时保留原战技缓冲和其他核心回归。

`python3 tools/run_dodge_buffer_checks.py` 驱动生产Runtime的输入、HUD和暂停路径；CI执行同一入口。相关旧战斗输入、双摇杆、三段对练与自由试装训练场检查用于验证成熟操作未被替换。

`tools/run_dodge_distance_core_checks.py` 与 `tools/run_dodge_distance_checks.py` 定向检查不同帧率与抖动帧的2.7格落点、末帧表现、捕获方向、墙／树／剧情门、排队及存档边界，并核对原费用和保护时钟。同一检查可对旧提交编译运行，复现末帧超额位移；更正旧“末帧走满整帧”断言时保留其余姿态、冷却、无敌与步态断言。

实际Unity程序集编译、离线输入与OnGUI记录各自只证明对应范围。原生Frontier场景运行、实体手柄、GPU、Player构建试玩及手感评价仍为 **`NATIVE_UNVERIFIED`**，不以离线通过代替原生验收。
