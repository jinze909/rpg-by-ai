# 固定比例、逐帧连贯性与首次战斗卡顿修复

当前生产场景为 `Frontier.unity`，实际动画来自 Core 动作钟与 OnGUI 图格。原 SampleScene 的 Animator 没有被用作修复替身。本轮没有新增职业、地图、怪物、玩法或存档字段。原可玩 `ViolaMoves.png`、原地图布局和原任务内容保留。

## 修复的共同根因

| 问题 | 修复 |
|---|---|
| 留白和举起武器改变整个人大小 | 玩家/同伴全部动作注册到256画布、(128,240)脚底、0.75显示密度；规范按身体注册，武器只使用留白。移除按动作缩放整个人的运行时补偿。 |
| 四相迈步时脸、发型和脸大小变化 | 三职业共用原可玩金发身份对应的头部像素层；步行头部位置、大小、方向图格固定。上半身动作只移动颈部连接，不改变头大小。 |
| 朝上/下闪避、受击和防御仍是侧身 | 新的24格方向反应图实际接入小人；北向先锋剑盾握持按职业校正，游侠/法师保持各自原持械手。倒地不叠加站立头部。 |
| 同伴步行和支援动作比例/脸不一致 | 三人各用自己的固定头部与相同导入契约；北向站立使用正确的非施法图格，四相行走与支援动作分别检查。 |
| 普通怪与Boss行走更换结构或体积 | 修正普通怪和八个Boss迈步作者图、来源注册与原动作的比例；软泥保持无额外长尾，重甲与Boss保持原结构/材料/武器。炉心守卫待机引用已接受握持姿态，不能缩成小号攻击体。 |
| 连续瞄准在方向边界换身体行/武器口 | 起手捕获目标、身体方向；弹道从实际出生点到目标计算。弹道修正不再二次选择身体方向和生成点。玩家普攻/Q、同伴、普通射手使用同一规则，散射共用一个出生点。 |
| Boss射弹从普通人的弓口出生 | Boss从自身中心与各Boss已校准高度发射；聚能提示采用同一高度。保留原弹数、速度、伤害与AI节奏。 |
| 第一次受击或HUD遮挡时突然卡顿 | 44张闪白/轮廓图在导入阶段从源透明度生成，游戏启动时加载。受击和遮挡绘制只取缓存，不扫描大图、不分配完整CPU颜色阵列；遮挡描边不再叠加生成遮罩。 |
| 重导入后同伴/迈步图不能读透明度 | 生产Editor导入规则与.meta统一；源图readable，预生成遮罩GPU-only，全部Point/无mipmap/无损。清理绘图缓存不会销毁借用的Resources贴图。 |

已保留上一轮修复：位移驱动四相步幅、明确攻击移动规则、真实接触帧、像素世界投影、树根固定与错峰树冠、低音量材质脚步、战斗HUD淡化与敌人轮廓、完整任务区域及封印支路碰撞边界。

## 已执行的检查

- 38组生产Core回归，包含主线/扩展旅程、保存恢复、关卡封锁、30秒连续行走、扫碰撞、攻击取消与接触时间、效果生命周期。
- 2160个连续方向/距离/武器组合，检查目标射线、真实出生点、身体方向行与发射高度；另外核对起手后改变鼠标、旅行、非法目标坐标。
- 156个玩家、84个同伴、99个普通怪/Boss状态组合。核对每次绘制的实际像素密度、裁切边界、方向、固定头部、准备/释放、闪避、防御、受击与倒地。
- 1350个离线生产Runtime/GUI布局状态，文本溢出为零；五个HUD区后方的实际敌人同时受击，检查实体描边不被闪白再次遮盖。
- 原森林Boss完整战斗：523个20ms模拟帧、103个绘制记录，确实完成原AI、预警、接触、闪避、胜利与尸体消散；其余七个Boss保留动作阶段检查。
- 121张PNG完整解码、404个非空/无越界图格、215个唯一GUID、1209个字体字符；44张遮罩重新按透明度计算并逐像素比较。
- 公开重导入入口在隔离目录实际执行，22张角色图、44张遮罩和头部注册表逐字节一致。
- 生产Editor导入方法通过离线声明实际调用检查75张贴图；Editor与原生PlayMode测试源码编译检查通过。
- 不可读的大Boss源图仍能使用预生成遮罩：CPU源图读取为零，1000次重复绘制复用同一贴图，清理不会销毁借用资源。

技术检查不能判断每一处肢体是否自然。12张逐帧接触图已人工查看脸、头身比例、四方向、单一武器、握持、图格裁切、敌人轮廓和Boss结构；实际场景与动作时间轴另有离线预览。
